# 제품 요구사항 명세서 (PRD): Spectrum
> A modern, fast, and engaging community platform.

## 1. 개요 (Vision)

Spectrum은 기존의 전통적인 게시판 시스템을 재해석하여, Vercel 기반의 Jamstack 아키텍처 위에서 빠르고, 안정적이며, 뛰어난 사용자 경험을 제공하는 모던 커뮤니티 플랫폼을 구축하는 것을 목표로 합니다. 실시간 상호작용, 유연한 콘텐츠 관리, 손쉬운 확장을 핵심 가치로 삼습니다.

## 2. 목표 및 핵심 원칙

*   **압도적인 속도:** Next.js의 정적/증분 생성을 통해 매우 빠른 페이지 로딩 속도를 제공합니다.
*   **최고의 사용자 경험(UX):** AJAX 기반의 동적인 상호작용(댓글, 좋아요 등)을 통해 페이지 새로고침 없는 부드러운 사용성을 제공합니다.
*   **관리 용이성:** 직관적인 관리자 대시보드를 통해 사용자, 게시판, 콘텐츠를 손쉽게 관리합니다.
*   **확장성:** 서버리스 아키텍처를 통해 트래픽 증가에 유연하게 대응하고, 기능 단위(serverless function)의 독립적인 개발 및 배포를 지향합니다.

## 3. 제안 기술 스택 (Vercel Native)

*   **프론트엔드:** **Next.js (React)** - Vercel 배포 및 성능 최적화에 가장 이상적입니다.
*   **백엔드 API:** **Python (FastAPI)** - Vercel Serverless Functions로 배포하여, 기존 Python 개발 경험을 활용하면서 확장성 있는 API를 구축합니다.
*   **데이터베이스:** **Neon** 또는 **Supabase** (Serverless PostgreSQL) - 서버리스 환경과 잘 맞고, 프리티어를 제공하여 초기 개발 비용을 절감합니다.
*   **인증:** **NextAuth.js** - 소셜 로그인(Google, GitHub 등)과 자격 증명 기반 로그인을 손쉽게 구현합니다.
*   **UI/스타일링:** **Tailwind CSS** + **shadcn/ui** - 생산성과 디자인 일관성을 높입니다.
*   **파일 스토리지:** **AWS S3** 또는 **Cloudflare R2** - Vercel의 무상태(stateless) 환경에 맞춰 파일 업로드를 처리합니다.
*   **배포:** **Vercel** - 프론트엔드와 서버리스 백엔드를 CI/CD 파이프라인으로 통합 배포합니다.

## 4. 기능 요구사항 (Features)

### 4.1. 사용자 인증 (P0)
*   **[USER-001]** 사용자는 이메일과 비밀번호를 통해 회원가입할 수 있어야 합니다.
*   **[USER-002]** 가입 시 사용자 이름, 닉네임, 이메일은 시스템 내에서 고유해야 합니다.
*   **[USER-003]** 사용자는 가입한 정보로 로그인 및 로그아웃을 할 수 있어야 합니다.
*   **[USER-004]** 사용자는 Google, GitHub 등 소셜 계정을 통해 간편하게 로그인/회원가입할 수 있어야 합니다. (NextAuth.js 활용)
*   **[USER-005]** 시스템에 최초로 가입한 사용자는 자동으로 '관리자(Admin)' 권한을 부여받습니다.

### 4.2. 사용자 프로필 및 마이페이지 (P1)
*   **[USER-006]** 사용자는 자신의 프로필 정보(닉네임, 프로필 이미지)를 수정할 수 있는 '마이페이지'를 가져야 합니다.
*   **[USER-007]** 마이페이지에서는 자신이 작성한 게시글과 댓글 목록을 확인할 수 있어야 합니다.
*   **[USER-008]** 읽지 않은 알림 목록을 확인하고, 클릭 시 해당 게시글로 이동할 수 있어야 합니다.

### 4.3. 게시판 (Boards) (P0)
*   **[BOARD-001]** 관리자는 여러 개의 독립된 게시판을 생성하고, 이름과 설명을 편집할 수 있어야 합니다.
*   **[BOARD-002]** 게시판별로 접근 권한을 설정할 수 있어야 합니다. (`access_level`: `PUBLIC` / `AUTHENTICATED` / `ADMIN`)
*   **[BOARD-003]** 모든 사용자는 접근 권한이 허용된 게시판의 목록을 볼 수 있어야 합니다.
*   **[BOARD-004]** 게시판 내에서 글을 분류할 수 있는 '카테고리(게시판별)'를 관리자가 생성/관리할 수 있어야 합니다.

### 4.4. 게시글 (Posts) (P0)
*   **[POST-001]** 사용자는 권한이 있는 게시판에 '공지'를 제외한 새로운 글을 작성할 수 있어야 합니다.
*   **[POST-002]** 글 작성 시, 마크다운(Markdown)을 지원하는 리치 텍스트 에디터를 제공해야 합니다.
*   **[POST-003]** 사용자는 글에 이미지나 파일을 첨부할 수 있어야 합니다. (파일은 S3/R2에 업로드)
*   **[POST-004]** 글 목록은 페이지네이션(Pagination)을 지원하며, 최신순으로 정렬되어야 합니다. 단, '공지'글(복수 가능)은 항상 상단에 고정되며 모든 페이지에서 반복 노출되어야 합니다.
*   **[POST-005]** 사용자는 제목, 내용, 작성자 기준으로 게시글을 검색할 수 있어야 합니다.
*   **[POST-006]** 글 작성자 본인 혹은 관리자는 글을 수정하거나 삭제할 수 있어야 합니다.
*   **[POST-007]** 관리자만 '공지' 속성의 글을 작성/설정할 수 있어야 합니다.
*   **[POST-008]** 게시글 작성 시 카테고리 선택은 필수이며, 각 게시판에는 최소 1개의 기본 카테고리가 존재해야 합니다.

### 4.5. 상호작용 (Interaction) (P0)
*   **[INTER-001]** 로그인한 사용자는 게시글에 '좋아요'를 누르거나 취소할 수 있어야 합니다. (페이지 새로고침 없이)
*   **[INTER-002]** 게시글의 '좋아요' 수는 실시간으로 반영되어야 합니다.
*   **[INTER-003]** 로그인한 사용자는 게시글에 댓글을 작성할 수 있어야 합니다. (페이지 새로고침 없이)
*   **[INTER-004]** 댓글 작성자 본인 혹은 관리자는 댓글을 삭제할 수 있어야 합니다.

### 4.6. 알림 (Notifications) (P1)
*   **[NOTI-001]** 자신이 작성한 글에 다른 사용자가 댓글을 달면, 글 작성자에게 실시간 알림이 생성되어야 합니다.
*   **[NOTI-002]** 사용자는 네비게이션 바 등에서 읽지 않은 알림의 개수를 확인할 수 있어야 합니다.
*   **[NOTI-003]** 알림 클릭 시, '읽음' 상태로 변경되고 해당 댓글이 있는 게시글 위치로 스크롤이 이동해야 합니다.

### 4.7. 관리자 기능 (Admin) (P1)
*   **[ADMIN-001]** 관리자는 모든 사용자 목록을 확인하고, 특정 사용자를 '차단(Banned)'하거나 관리자 권한을 부여할 수 있어야 합니다.
*   **[ADMIN-002]** 차단된 사용자는 시스템에 로그인할 수 없어야 합니다.
*   **[ADMIN-003]** 관리자는 모든 게시판과 카테고리를 생성, 수정, 삭제할 수 있어야 합니다.
*   **[ADMIN-004]** 관리자는 모든 게시글과 댓글을 강제로 삭제할 수 있어야 합니다.

## 5. 배포 및 운영

*   **소스 코드:** GitHub Repository에서 관리합니다.
*   **배포:** Main 브랜치에 코드가 푸시되면 Vercel의 CI/CD 파이프라인을 통해 자동으로 프론트엔드와 서버리스 기능이 배포됩니다.
*   **환경 변수:** 데이터베이스 접속 정보, JWT 시크릿 키, S3 접속 키 등 민감 정보는 Vercel 프로젝트의 환경 변수 설정을 통해 안전하게 주입합니다.
